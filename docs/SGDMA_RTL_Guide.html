SG DMA, 처음부터 RTL까지

DMA가 무엇인지부터 시작해서, Scatter-Gather가 왜 필요한지, 그리고 이 레포의 sgdma_top이 dmac_sg.v로 descriptor를 읽어 전송 엔진에 넘기는 과정을 순서대로 따라갑니다. 예시 값은 모두 tb_sg_dma.sv의 SAN-005(3-descriptor gather)에서 가져왔습니다.

01DMA란 무엇인가

메모리의 A 위치에서 B 위치로 4KB를 옮긴다고 해봅시다. CPU가 직접 하면 "8바이트 읽기 → 8바이트 쓰기"를 512번 반복해야 하고, 그동안 CPU는 다른 일을 못 합니다.

DMA(Direct Memory Access)는 이 복사만 전담하는 하드웨어입니다. CPU는 "어디서(src), 어디로(dest), 몇 바이트(length)"만 알려주고 손을 뗍니다. DMA가 버스 마스터가 되어 직접 읽고 쓰고, 끝나면 인터럽트(IRQ)로 알려줍니다. 이삿짐센터에 주소 두 개와 짐 양만 알려주는 것과 같습니다.

RTL을 읽기 전에 알아둘 용어

src / dest

읽을 곳과 쓸 곳. axi_dmac은 각각 AXI-MM, AXI-Stream, FIFO 중에서 고를 수 있고, 이 레포는 메모리→메모리(MM2MM)로 고정되어 있습니다.

beat / burst

beat는 한 사이클에 옮기는 데이터 1개(64비트면 8바이트), burst는 주소 한 번에 연속으로 오가는 beat 묶음(arlen+1개). 이 레포는 최대 128B = 16 beat.

transfer

요청 하나의 전체 복사. 길이가 burst보다 길면 DMA가 내부에서 여러 burst로 잘라서 보냅니다. SG에서는 descriptor 1개 = transfer 1개입니다.

EOT

End Of Transfer. transfer가 다 끝났다는 신호이고, 보통 IRQ로 이어집니다. RTL에서는 eot, dma_eot, req_eot로 보입니다.

valid / ready

모듈 사이 요청은 모두 AXI식 핸드셰이크입니다. valid와 ready가 같은 클럭에 1이면 하나가 넘어갑니다.

util_axis_fifo

블록 사이에 놓이는 FIFO. 원래는 클럭이 다른 블록을 잇는 CDC 용도지만, 이 레포는 단일 클럭이라 모두 동기 FIFO로 합성됩니다.

02왜 Scatter-Gather가 필요한가

단순 DMA는 "연속된 한 덩어리"만 옮깁니다. 그런데 실제 메모리 버퍼는 흩어져 있는 경우가 많습니다. 리눅스에서 앱이 잡은 버퍼는 가상 주소로는 연속이지만, 물리 주소로는 4KB 페이지가 여기저기 흩어져 있습니다. 네트워크 패킷도 헤더와 payload가 따로 있는 경우가 흔합니다.

단순 DMA로 이걸 처리하려면 조각마다 CPU가 레지스터를 쓰고, 인터럽트를 받고, 다음 조각을 다시 설정해야 합니다. 조각이 수백 개면 CPU가 결국 계속 붙어 있어야 합니다.

Scatter-Gather는 이렇게 해결합니다. CPU가 "할 일 목록(descriptor)"을 메모리에 미리 연결 리스트로 써두고, DMA에는 첫 descriptor 주소 하나만 알려줍니다. 그다음부터는 DMA가 스스로 목록을 읽어가며 끝까지 처리합니다.

03이 레포의 구성: sgdma_top.v

sgdma_top은 로직이 없는 wrapper입니다. ADI axi_dmac(hdl_2026_r1)을 하나 인스턴스하고, 파라미터를 고정하고, 쓰지 않는 포트를 묶어둡니다. 그런데 이 파라미터들이 RTL 안에서 어떤 generate 블록이 살아남는지를 정하기 때문에, 코드를 읽기 전에 먼저 알아야 합니다.

ADI 코드에 적용된 패치 1건

scripts/import_adi_dmac.sh가 ADI 원본을 복사한 뒤 patches/0001-burst-memory-zero-replication.patch를 적용합니다. 원본과의 차이는 이것 하나뿐입니다.

// axi_dmac_burst_memory.v - reg [...] dest_burst_len_data = {DMA_LENGTH_ALIGN{1'b1}}; + reg [...] dest_burst_len_data = (1 << DMA_LENGTH_ALIGN) - 1;

MM→MM이면 DMA_LENGTH_ALIGN = 0이 되고, 원본 식은 {0{1'b1}}, 즉 0번 반복(zero replication)이 됩니다. Verilog에서 허용되지 않는 식이라 시뮬레이터에 따라 에러나 경고가 납니다. 패치 식은 같은 경우 (1<<0)-1 = 0으로 의미는 같고 문법은 합법적입니다. 덕분에 길이 정렬 제약이 없어서 바이트 단위 길이를 그대로 검증할 수 있습니다.

04Descriptor 형식

dmac_sg.v는 descriptor 하나를 64비트 × 6 beat = 48바이트로 읽습니다. 그래서 AR 값이 고정되어 있습니다: arlen=5(6 beat), arsize=3(8바이트), arburst=INCR. 읽어오는 beat 순서대로 hwdesc_counter가 0~5를 세고, case문이 각 beat를 해당 레지스터에 저장합니다. TB의 write_desc 태스크가 이 형식대로 메모리에 씁니다.

beat오프셋[63:32][31:0]의미 · 이 레포에서
0+0x00idflags[1:0]bit0 = LAST, bit1 = EOT_IRQ. SAN-005는 D0·D1에 2'b00, D2에 2'b11
1+0x08dest_addr하위 32비트만 사용, 하위 3비트 버림
2+0x10src_addr하위 32비트만 사용, 하위 3비트 버림
3+0x18next_desc_addr다음 descriptor 주소. LAST가 1이면 읽지만 쓰이지 않음
4+0x20x_lengthy_lengthx_length = 바이트 수 − 1 (TB: len_bytes - 1). y는 2D=0이라 무시
5+0x28dest_stridesrc_stride2D 전용, 이 레포에서는 무시 (TB는 0을 씀)

주소 레지스터들은 [ADDR_WIDTH-1 : BYTES_PER_BEAT_WIDTH] = [31:3]로 선언되어 하위 비트를 저장하지 않습니다. 그래서 descriptor 주소와 src/dest 주소가 모두 8바이트 정렬이어야 하고, 정렬이 안 된 값은 하위 비트가 조용히 버려집니다. SAN-007에서 SG_ADDRESS에 0xFFFFFFFF를 쓰면 0xFFFFFFF8로 읽히는 것이 이 때문입니다.

05RTL 계층 구조

filelists/rtl.f에는 30여 개 파일이 있지만, 이 구성에서 실제로 인스턴스되는 것은 일부입니다. 앰버가 SG 관련, 틸이 데이터 이동 경로, 회색은 filelist에는 있지만 generate로 빠지는 블록입니다. 시뮬레이션 계층 경로로 적었습니다.

tb_sg_dma.dut : sgdma_top // wrapper, 파라미터 고정만 └─ i_axi_dmac : axi_dmac.v // top: 포트·파라미터 정리 ├─ i_regmap : axi_dmac_regmap.v // CPU가 보는 레지스터 (AXI4-Lite slave) │ ├─ up_axi // AXI-Lite ↔ up_wreq/up_rreq 변환 │ └─ axi_dmac_regmap_request.v // 전송 요청 레지스터, SG_ADDRESS, 요청 FIFO └─ i_transfer : axi_dmac_transfer.v // 전송 엔진 전체 ├─ i_reset_manager // ENABLE/정지 시퀀스 ├─ i_dmac_sg : dmac_sg.v // descriptor → 요청 변환 ├─ i_dmac_flock, i_2d_transfer // DMA_2D_TRANSFER=0 → 생성 안 됨 └─ i_request_arb : request_arb.v // 데이터 무버 ├─ i_req_gen // 요청 → burst 단위 ID 발급 ├─ i_src_dma_mm // AR 발행, R 수신 (address_generator) ├─ i_store_and_forward // axi_dmac_burst_memory, 패치 지점 ├─ i_dest_dma_mm // AW/W 발행, B 수신 (address_generator, response_handler) ├─ i_response_manager // dest 응답 → 전송 완료 보고 ├─ i_src_dma_stream/fifo, i_dest_dma_stream/fifo // TYPE=MM → 생성 안 됨 └─ i_*_slice, i_*_fifo, i_sync_* // 파이프라인·FIFO (단일 클럭)
핵심 관찰. SG 기능은 dmac_sg.v 한 파일(338줄)에 거의 다 들어 있습니다. 나머지 엔진은 원래 있던 단순 DMA 그대로이고, SG는 그 앞에 "요청을 자동으로 만들어주는 블록"으로 붙어 있을 뿐입니다. 파형을 볼 때는 tb_sg_dma.dut.i_axi_dmac.i_transfer.i_dmac_sg부터 열면 됩니다.

06SG가 끼어드는 지점: ctrl_hwdesc MUX

axi_dmac_transfer.v에서 SG 모드와 일반 모드는 MUX 하나로 갈립니다. CONTROL 레지스터 bit2(HWDESC)가 ctrl_hwdesc이고, 이 값에 따라 엔진에 들어가는 주소·길이·valid가 CPU 레지스터 값이냐 dmac_sg가 읽어온 descriptor 값이냐가 정해집니다. TB는 CONTROL에 0x5(ENABLE|HWDESC)를 써서 SG 쪽을 고릅니다.

2D가 꺼져 있으므로 이 레포에서 실제로 살아 있는 코드는 axi_dmac_transfer.v의 generate if (DMA_2D_TRANSFER == 1) ... else 중 else 쪽입니다. 이 몇 줄이 SG와 기존 엔진의 접점 전부입니다.

assign dma_req_valid = ctrl_hwdesc ? dma_sg_out_req_valid : req_valid_gated; assign req_ready_gated = ctrl_hwdesc ? dma_sg_in_req_ready : dma_req_ready; assign dma_req_dest_address = ctrl_hwdesc ? dma_sg_out_dest_address : req_dest_address; assign dma_req_src_address = ctrl_hwdesc ? dma_sg_out_src_address : req_src_address; assign dma_req_length = ctrl_hwdesc ? dma_sg_x_length : req_x_length; // 위쪽 (generate 밖) assign req_eot = ctrl_hwdesc ? (dma_eot & dma_sg_hwdesc_eot) : dma_eot; assign dma_sg_in_req_valid = ctrl_hwdesc ? req_valid_gated : 1'b0;

둘째 줄을 보면 SG 모드에서 regmap 요청의 ready는 dma_sg_in_req_ready, 즉 dmac_sg FSM이 IDLE일 때만 1입니다. 체인이 도는 동안에는 새 submit이 대기합니다. req_eot 줄은 SG 모드에서 모든 descriptor 완료마다 IRQ가 나는 것이 아니라, EOT_IRQ 플래그가 켜진 descriptor가 끝날 때만 완료가 올라간다는 뜻입니다.

07dmac_sg.v 내부

dmac_sg는 세 부분입니다. FSM이 AXI 읽기를 발행하고, 필드 레지스터가 6 beat를 받아 저장하고, FIFO 3개가 바깥(regmap/엔진)과 연결합니다.

FSM 4개 상태

코드 읽을 때 짚을 점

  1. next_desc_addr는 두 곳에서 갱신됩니다. 처음 시작할 때 addr FIFO의 값(SG_ADDRESS)으로, 이후에는 beat 3에서 읽은 next 포인터로. 그래서 m_axi_araddr = {next_desc_addr, 3'b0} 한 줄이 첫 descriptor와 이후 descriptor를 모두 처리합니다.
  2. prefetch가 자연스럽게 일어납니다. desc FIFO가 D0를 받아가면 FSM은 바로 SEND_ADDR로 돌아가 D1을 읽기 시작합니다. 엔진이 D0 데이터를 옮기는 동안 다음 descriptor가 미리 준비됩니다. SOR DESC-009에 적어둔 SG AR 간격(80ns)이 바로 이 동작입니다.
  3. id FIFO가 "진행 중인 descriptor"를 기억합니다. 엔진에서 dma_eot가 올 때마다 하나씩 꺼내고(fifo_out_ready = resp_in_valid), 꺼낸 항목의 EOT 플래그가 1이면 IRQ로 이어집니다. 깊이가 4(ADDRESS_WIDTH=2)라서 이 FIFO가 차면 splitter가 막혀 prefetch도 멈춥니다. FIFO가 비면 마지막으로 꺼낸 값이 출력에 남기 때문에 DESCRIPTOR_ID가 마지막 완료 id(SAN-005의 0xB2)를 보여줍니다.
  4. addr/desc FIFO는 ADDRESS_WIDTH(0), 즉 저장 공간이 1칸인 스테이지입니다. 버퍼라기보다 핸드셰이크를 끊어주는 레지스터에 가깝습니다.
  5. m_axi_rresp는 포트에만 있고 어디에도 쓰이지 않습니다. descriptor fetch에서 에러 응답이 와도 그 데이터로 계속 진행합니다 (SOR ERR-002).

08SAN-005로 보는 동작 순서

  1. 초기 설정 (한 번만): TB가 IRQ_MASK = 0x1(SOT 마스크, EOT 허용), CONTROL = 0x5(ENABLE | HWDESC)를 씁니다.
  2. descriptor 작성: write_desc로 0x1100, 0x1140, 0x1180에 D0~D2를 씁니다. D2만 flags=2'b11.
  3. 시작: start_sg(0x1100)이 SG_ADDRESS(0x47C)에 0x1100, TRANSFER_SUBMIT(0x408)에 1을 씁니다.
  4. 요청 진입: regmap_request가 요청을 내보내고, ctrl_hwdesc=1이라 dma_sg_in_req_valid로 dmac_sg의 addr FIFO에 들어갑니다.
  5. Fetch: FSM이 m_sg_axi로 AR 1번(araddr=0x1100, arlen=5), R 6 beat를 받아 필드를 채우고 DESC_READY로 갑니다.
  6. 전달: splitter가 필드는 desc FIFO(→ MUX → request_arb)로, id B0와 플래그는 id FIFO로 보냅니다. FSM은 곧바로 0x1140의 D1을 읽으러 갑니다.
  7. 데이터 이동: request_arb가 0x11000에서 128B(16 beat, burst 1개)를 읽어 burst_memory를 거쳐 0x21000에 씁니다. B 응답까지 받으면 dma_eot.
  8. 완료: dma_eot마다 id FIFO에서 1개를 꺼냅니다. B2를 꺼낼 때 EOT 플래그가 1이므로 req_eot → IRQ_PENDING[1] → irq. TB는 wait_irq 후 IRQ_PENDING을 읽어 그대로 써서 W1C로 지우고, DESCRIPTOR_ID가 0xB2인지 확인합니다.

09SG에 필요한 레지스터

RTL의 up_waddr는 32비트 워드 주소입니다. TB와 SFR 문서의 바이트 주소는 ×4 한 값입니다. 이름은 TB의 REG_* 상수를 따랐습니다.

바이트 주소RTL (워드)이름이 레포에서
0x0809'h020IRQ_MASKbit0 SOT, bit1 EOT. 1 = 마스크. 리셋값 0x3 (둘 다 막힘), TB는 0x1로 EOT만 허용
0x0849'h021IRQ_PENDING마스크 통과한 인터럽트. W1C
0x0889'h022IRQ_SOURCE마스크와 무관한 원래 소스
0x4009'h100CONTROLbit0 ENABLE, bit1 PAUSE, bit2 HWDESC. bit3 FRAMELOCK은 마스크되어 최대 0x7
0x4089'h102TRANSFER_SUBMIT1을 쓰면 체인 시작
0x4289'h10aTRANSFER_DONEtransfer id별 완료 비트맵
0x4549'h115DESCRIPTOR_ID완료된 descriptor의 id (읽기 전용)
0x47C9'h11fSG_ADDRESS첫 descriptor 주소. 하위 3비트 0 고정

SG 모드에서는 DEST_ADDRESS(0x410), SRC_ADDRESS(0x414), X_LENGTH(0x418) 같은 일반 전송 레지스터가 엔진에 쓰이지 않습니다. MUX가 descriptor 쪽을 고르기 때문입니다.

10읽는 순서와 SOR 연결

읽는 순서

  1. rtl/sg_dma/sgdma_top.v의 파라미터 블록. 어떤 generate가 살아 있는지 먼저 정합니다 (3장 표).
  2. dmac_sg.v 전체. 독립적이고 짧아서 SG 개념을 RTL로 확인하기 가장 좋습니다. FSM → 필드 case문 → FIFO 3개 → splitter 순으로.
  3. axi_dmac_transfer.v의 i_dmac_sg 인스턴스와 그 아래 ctrl_hwdesc ? MUX (DMA_2D_TRANSFER의 else 블록).
  4. axi_dmac_regmap.v, axi_dmac_regmap_request.v에서 CONTROL, SUBMIT, SG_ADDRESS, IRQ 처리.
  5. request_arb.v는 1200줄이라 전부 읽지 말고 MM 쪽 인스턴스만 따라갑니다. i_src_dma_mm → address_generator.v → i_store_and_forward → i_dest_dma_mm.
  6. 이 순서를 따라가면서 tb_sg_dma.sv의 SAN-004(단일), SAN-005(체인) 파형을 함께 보면 신호 이름이 바로 연결됩니다.

단순 DMA를 직접 만들어보는 중이라면 5번이 그 설계(req_gen → FIFO → rd/wr master)와 거의 같은 구조라 비교하면서 보기 좋습니다.

RTL 위치와 SOR 요구사항

SOR의 descriptor·에러 요구사항이 RTL의 어느 줄에서 나오는지 연결해 두었습니다. 시나리오를 구체화할 때 어디를 probe할지 정하는 데 씁니다.

AR 고정값 DESC-001

dmac_sg.v의 assign m_axi_arlen = 'h5, arsize = 3'h3, arburst = 2'h1.

필드 배치 DESC-002, 007

case (hwdesc_counter) 블록. x_length는 rdata[63:32]를 24비트 레지스터에 넣어 상위 8비트가 잘립니다.

LAST / next DESC-003, 004

FSM의 STATE_DESC_READY 분기 (hwdesc_flags & MASK_LAST_HWDESC).

IRQ 조건 DESC-005

axi_dmac_transfer.v의 req_eot = dma_eot & dma_sg_hwdesc_eot.

DESCRIPTOR_ID DESC-006

i_fifo의 m_axis_data. 비어 있으면 마지막으로 꺼낸 값을 유지합니다.

8B 정렬 DESC-008

주소 레지스터 선언 범위 [...:BYTES_PER_BEAT_WIDTH_SG], araddr의 {..., 3'b0}.

prefetch DESC-009

DESC_READY → SEND_ADDR 바로 복귀 + i_fifo 깊이 4가 한도.

fetch 에러 ERR-002

m_axi_rresp 미사용. FSM은 rvalid, rlast만 봅니다.

자기 자신을 가리키는 next ERR-004

FSM 탈출 경로는 LAST와 sg_enable=0뿐입니다. CONTROL.ENABLE=0이 reset_manager를 거쳐 sg_enable을 내리는지가 확인 지점입니다.
